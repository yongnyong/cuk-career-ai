방침: 회의에서 나온 8개 아이디어를 **전부 구현한다.** 대신 단계(1→2→3)로 쌓아서, 일정이 밀리면 뒤 단계부터 줄인다. 각 단계가 끝날 때마다 운영 배포 가능한 상태를 유지한다.

## 3. 기능별 구현 방향

### 1단계 — 보는 법

**C. 노드 크기 = 가중치**
- 이미 있는 값만으로 점수를 만든다: 직무 필수 여부(`required`), 그 노드가 열어 주는 실제 공고 수(`opportunities.length`), 공고 근거 신호(`evidence`, 필수 6·우대 5·활동 2·학교 1로 `selectRecommendedQuest`와 같은 가중치), 이 노드를 선수로 쓰는 노드 수.
- 3단계(대·중·소) 크기. 범례: "크면 먼저 — 필수이거나 공고에 자주 나오는 역량".
- 난이도는 근거 데이터가 없어 크기에 섞지 않는다. 대신 노드 상세에 학년 단계(기존 `progressionStage`)를 보여 준다.
- 위치: `web/src/lib/treeProgression.ts`에 `nodeWeight(node, tree)` 순수 함수, 테스트 `web/tests/`.

**A. 방사형 보기 (기본)**
- `layoutRadial(tree)`를 추가하고 기존 세로 레이아웃은 토글로 남긴다.
- 가운데 = 목표 직무. 고리 = 기존 `depth`(안쪽일수록 먼저). 부채꼴 = 노드 분류(`kind`: 전공·자격·어학·실무·경험), 부채꼴 배경에 분류 이름.
- 노드가 많으면 고리 반지름을 노드 수에 맞춰 늘리고, 같은 고리 안에서는 선수 노드 각도의 평균으로 정렬해 간선 꼬임을 줄인다(기존 barycenter 방식의 극좌표판).
- React Flow 좌표만 바꾸면 되므로 노드 컴포넌트·상세 패널은 그대로 쓴다.

**B. 서브트리 확대 + 유리한 방향**
- 노드 상세의 "자세히 보기" → 그 노드를 가운데 둔 방사형을 다시 그린다.
  - 1번째 고리: 이 노드 다음에 열리는 노드(이 노드를 선수로 갖는 노드, 재귀).
  - 2번째 고리: "이 노드가 유리한 곳". 해당 노드와 하위 노드의 `opportunities`·`evidence`에서 **직무 태그(`jobs`)별로 묶고, 그 안에 기관명(`org`)**을 단다. 공고 수가 많을수록 크게.
  - 명예의 전당 인물 중 이 노드를 가진 사람도 한 고리로 보여 준다("젠슨 황도 찍은 노드").
- 공고 데이터에 업종 필드가 없으므로 "업계"는 직무 태그 기준. 공고 0건이면 "아직 이 역량을 요구하는 열린 공고가 없어요". 지어내지 않는다.
- 뒤로 가기·다른 노드로 이동하면 계속 확대(breadcrumb).

### 2단계 — 따라 하기

**D. 명예의 전당**
- 정적 데이터 `web/src/lib/data/hallOfFame.ts`, 15명 내외. 각 인물: 한 줄 소개, 분야, 학과 연결, 스킬 노드 10~15개(선수 관계 포함 → 방사형으로 그대로 그림).
- 노드는 가능한 한 **기존 카탈로그 스킬 ID**를 쓴다(E 점수 계산용). 카탈로그에 없는 것은 `custom` 노드(이름·분류만).
- 초안은 생성형 AI로 만들고 팀이 검토해 고정한다. 실시간 생성 안 함(시연 지연·환각 방지).
- 화면에 **"AI가 공개 이력을 바탕으로 추정한 가상 스킬트리이며 본인이 작성한 것이 아님"** 표시(대회 준수사항).
- 순위는 "멘토로 지정된 수" 기준. 3단계 전에는 고정값, 3단계 후에는 실제 집계. 팀원 양호용은 3위 자리에 실제 본인 기록으로 넣는다.

**E. 멘토 지정 + 점수**
- "멘토로 지정" → `state.mentorId` 저장.
- 점수 = 멘토 노드 중 내가 완료한 노드의 가중치 합 ÷ 멘토 노드 가중치 합 × 100. 인증 1.0, 자기 체크 0.6(기존 EXP 100:60과 같음). 가중치는 C의 `nodeWeight`.
  - 유사도(자카드)가 아니라 **채움률**. "다 찍으면 100점"과 맞고, 내 트리에 다른 노드가 많아도 깎이지 않는다.
- 트리 상단에 "스티브 잡스까지 23점" 막대, 멘토와 겹치는 노드에 멘토 표시, 노드를 찍어 점수가 오르면 짧은 연출.
- 멘토 노드 중 내 직무 트리에 없는 것은 "멘토 따라잡기" 목록 → 버튼 한 번으로 내 트리에 추가(F와 연결).

**F. 트리 커스터마이징**
- `state.customNodes[]`(id·이름·분류·선수·메모)와 `state.hiddenNodes[]`를 저장하고 `buildTree` 결과에 합친다. 원래 직무 템플릿은 건드리지 않는다.
- 커스텀 노드는 공고 근거가 없으므로 크기는 최소, "직접 추가" 표시. 진행률·EXP에는 포함, 추천 퀘스트 후보에서는 제외.
- 관리자 `TrackEditor.tsx`의 선수 관계 순환 방지(`sanitizeJob`)를 재사용.

### 3단계 — 함께 하기

**G. 트리 공유 SNS**
- 새 테이블(`api/app/main.py`의 `create_all`로 자동 생성):

  | 테이블 | 열 |
  | --- | --- |
  | `shared_trees` | id, user_id, 닉네임, 제목, 소개, 직무·학과, 트리 스냅샷 JSON, 공개 여부, 만든·고친 시각 |
  | `tree_likes` | tree_id, user_id |
  | `tree_comments` | id, tree_id, node_skill(없으면 트리 전체), user_id, 본문, 시각, 숨김 여부 |
  | `follows` | follower_id, followee_id |
  | `notifications` | id, user_id, 종류(좋아요·댓글·새 트리·구독), 대상, 읽음 |

- **공유는 스냅샷**: 사용자가 "공유하기"를 누른 시점의 트리(노드·상태·커스텀 노드)만 올린다. 프로필의 학번·학년 등은 넣지 않고 닉네임·직무·학과만. 다시 공유하면 갱신.
- 화면: `/community`(최신·인기·내 학과), `/community/[id]`(남의 트리를 방사형으로, 좋아요·댓글·구독), 내 트리에서 "공유하기", 헤더 알림 아이콘에 소셜 알림 추가(기존 `/notifications` 화면 재사용).
- 남의 트리를 보며 "이 트리 따라 하기" → E의 멘토처럼 지정 가능(명예의 전당과 같은 점수 로직).
- 관리: 신고 버튼 → 관리자 화면에서 숨김. 댓글 길이·빈도 제한. 탈퇴(`DELETE /api/me`) 시 공유 트리·댓글·좋아요·구독도 삭제.

**H. 노드별 꿀팁·인증 사진**
- 꿀팁 = `tree_comments`에서 `node_skill`이 있는 댓글. 내 트리 노드 상세에 "이 노드를 찍은 사람들의 팁" 목록(같은 스킬 ID의 공개 팁 모음).
- 인증 사진: 이미지 1장, 2MB 이하, 서버에서 다시 인코딩해 EXIF(위치 등) 제거. 업로드 전에 "얼굴·학번·성적표 등 개인정보가 보이지 않게" 안내. 공개 트리에서만 보임.
- 기존 증빙 업로드(`ProofField`)와는 분리: 증빙은 비공개 인증용, 인증 사진은 공개 자랑용.

## 5. 시연 장면 (3분 영상)

1. 지우 계정 → 방사형 트리. "큰 것부터 찍으면 돼요."
2. 상담면접 실습 확대 → 다음 노드, 이 역량을 찾는 기관, 같은 노드를 찍은 명예의 전당 인물.
3. 명예의 전당 → 멘토 지정 → "OOO까지 18점" → 노드 체크 → 점수 상승·레벨업.
4. 멘토 따라잡기로 노드 하나 내 트리에 추가.
5. 공유하기 → 커뮤니티 피드 → 다른 학생 트리에 좋아요·노드 꿀팁 → 알림.

## 6. 남은 확인 사항

1. **명예의 전당 인물.** 실존 인물은 "실제로 그랬냐"는 질문과 명예 문제가 생길 수 있다. 공개 이력이 분명하고 논란이 적은 인물을, 학과별(심리·사회복지·AI·경영·예술 등)로 섞어 고른다. 목록 초안을 팀이 확정.
2. **시연용 공유 트리 데이터.** 커뮤니티가 비어 보이지 않도록 팀원·지인 계정으로 실제 트리를 몇 개 공유해 둔다. 가짜 사용자를 실제 사용자처럼 꾸미지 않는다(시연 계정이면 "시연 계정" 표시).
3. **3단계 서버 배포 시점.** 11/23 API 서버는 `feat/agent-memory` 기준이므로, 3단계 배포 전에 서버 브랜치를 main과 맞출지 먼저 정한다.
