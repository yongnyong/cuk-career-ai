# 배포 계획

> 2026-11-16에 쓴 초기 계획 메모다. 실제 구성과 운영 방법은 README의 "8. 배포와 운영"을 본다.
> 계획과 달라진 점: Redis·워커 없음(수집은 서버 cron), 도메인은 DuckDNS 대신 sslip.io, 저장소는 공개.

목표: 12/2 제출 시 심사위원이 URL 하나로 접속할 수 있고, 12/4 본선 시연 중 죽지 않는 구성.

## 구성

```
[브라우저] ──HTTPS──> Vercel (web/ · Next.js)
                         │  API_URL
                         ▼
               VPS 1대 (Docker Compose)
               ├─ caddy     : HTTPS 자동 인증서, 리버스 프록시
               ├─ api       : FastAPI (공고·프로필·추천·챗봇)
               ├─ worker    : 알림 큐 작업 (D-7·3·1, 정정 재계산)
               ├─ postgres  : pgvector 포함 (공고·버전·근거 문단·임베딩)
               └─ redis     : 큐·멱등키
                         │
                         ▼
                 Gemini API (구조화·임베딩·답변)
```

- 웹은 Vercel: 무료, GitHub push마다 자동 배포, 미리보기 URL 제공.
- 서버는 직접 만든 VPS 1대: Postgres·Redis·워커를 한 곳에서 돌려 무료 PaaS의 절전(첫 요청 지연) 문제를 피한다.

## 도메인·HTTPS

- 도메인 구매 없이: DuckDNS 무료 서브도메인(`cuk-career.duckdns.org` 형태)을 VPS 고정 IP에 연결 → Caddy가 인증서를 자동 발급.
- 웹 주소는 Vercel 기본 도메인(`*.vercel.app`)을 제출 URL로 사용.

## 순서

1. GitHub 비공개 저장소 생성 → 이 폴더 push → 팀원 초대
2. Vercel에 저장소 연결, Root Directory `web` → 지금 상태(브라우저 저장 모드)로 먼저 공개 URL 확보
3. VPS 생성(Ubuntu 24.04) → Docker 설치 → 방화벽 80·443·22만 허용, SSH 키 로그인만
4. `api/` 구현 후 `docker compose up -d` → Caddy 도메인 연결
5. Vercel 환경변수 `API_URL` 설정 → 웹이 서버 데이터로 전환
6. 시드 스크립트로 시연 데이터 적재, DB 백업 파일 보관

## 비밀값

- `GEMINI_API_KEY`, `DATABASE_URL`, `ADMIN_TOKEN`은 서버 `.env`에만 둔다. 저장소에 올리지 않는다(`.env.example`만 커밋).
- Gemini 키는 서버에서만 쓴다. 웹(브라우저)에는 절대 넣지 않는다.
- 관리자 화면(공고 등록·정정)은 서버 연결 시 `ADMIN_TOKEN`으로 보호한다. 지금은 시연 편의상 열려 있다.

## 시연 안전장치

- `API_URL`이 비어 있거나 서버가 응답하지 않으면 웹은 로컬 모드(브라우저 저장)로 동작한다 → 현장 네트워크 문제에도 시연 가능. 단, 이때는 서버 계정으로 로그인할 수 없고 시연용 계정을 쓴다.
- 웹은 `/api/*` 요청을 `API_URL`로 넘긴다(Next.js rewrites). 브라우저 입장에서는 같은 출처라 세션 쿠키가 그대로 동작한다.
- 12/1 기능 동결 후 서버 스냅샷 1회, DB 덤프 1회.
- Gemini 호출은 공고 해시 기준으로 결과를 저장해 재호출하지 않는다. 일일 호출 상한을 둔다.
- 시연 영상(3분)은 배포 URL에서 녹화한다.

## 수집 준수사항 (서버 수집기 구현 시)

- 사이트별 robots.txt를 요청 전에 확인한다. 학교 홈페이지의 `/_attach/`, `/_custom/`, `/_res/` 경로는 수집하지 않는다.
- 공지 제목과 본문만 수집하고 요청 간격은 3초 이상 둔다.
- 명단·연락처 등 개인정보가 포함된 본문은 저장 전에 걸러내고 Gemini에도 보내지 않는다.
- 모든 공고에 출처·확인 시각·원문 링크를 저장한다.
