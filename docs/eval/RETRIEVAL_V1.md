# 공고 검색 1차 개선 결과

2026-11-24 기준으로 이전 커밋 `84e1de7`의 검색·웹 추천 코드와 수정본을 비교했다. Gemini 임베딩과 생성 모델 호출은 사용하지 않았다.

## 적용 내용

- 한국어의 무조건적인 두 글자 분해를 제거했다. 조사 제거와 명시적인 업무 용어 사전으로 복합어를 찾는다. 형태소 분석기 도입은 후속 작업이다.
- AI·데이터·분석 등 폭넓은 표현의 키워드 점수 가중치를 낮췄다. SQL과 SQLD의 정확한 명칭은 보존한다.
- 취업 질의는 목표 직무와 그 직무의 필수 역량으로 만든다. 보유 공통 자격증이나 일반적인 직무 소개 문장이 검색을 지배하지 않게 했다.
- 미분류 공고는 검증된 원문 문단에 구체적인 직무 내용이 있어야 탐색 후보로 들어온다. 제목만 일치하는 미분류 공고는 목록에서 보류한다.
- 기존 규칙으로 연결된 공고는 검색에서 누락되어도 보존한다. 검색 장애, 성공한 빈 결과, 창업 목표 변경을 함께 검사했다.

## 개발·회귀용 합성 평가

`opportunity-relevance-v1.json`은 가상 공고 15건과 질의 30개다. AI·심리·SQL·창업의 9개 주제에 세 표현씩 27개, 관련 공고가 없는 질의 3개를 더했다. 개발자가 적합 2·일부 관련 1·무관 0을 부여했다. 이번 가중치 조정에 사용한 자료이므로 독립적인 품질 검증은 후속 검토가 필요하다. 표현 변형 세 개를 독립 표본으로 해석하지 않는다.

| 지표 | 이전 | 수정 후 |
|---|---:|---:|
| 상위 3개 무관 공고 수, 전체 질의 합계 | 22 | 15 |
| 상위 3개 적합 비율, 양성 27개 평균 | 0.3704 | 0.3827 |
| 상위 20개 재현율, 양성 27개 평균 | 0.9074 | 0.9074 |
| NDCG@3, 양성 27개 평균 | 0.9600 | 0.9665 |
| 정답 없는 질의의 상위 3개 오추천 수 | 0 | 0 |

상위 3개 적합 비율은 항상 3으로 나눈다. 정답이 한두 건인 질의와 빈 슬롯도 포함되므로 1.0이 최적값이 되는 질의만으로 구성된 평가가 아니다. NDCG는 적합 2와 일부 관련 1을 반영한 순위 지표다. 숫자로는 소폭 개선이며 실제 사용자 전체의 개선율로 확대하지 않는다.

## 실제 로컬 공고 비교

공개 공고 425건, 기준일 2026-11-24, 민지·지우의 3·4학년과 서준의 두 목표를 비교했다. 기존 직무 카탈로그와 지원 조건 판정은 동일하게 사용했다. 실제 공고 결과에는 독립적인 정답 라벨이 없어 정밀도 개선율을 계산하지 않았다.

| 시연 | 이전 맞춤 공고 수 | 수정 후 | 관찰 |
|---|---:|---:|---|
| 민지 3학년 | 52 | 26 | 기존 규칙 연결 공고를 유지하고 미분류 유입을 제한 |
| 민지 4학년 | 53 | 27 | 모집 조건 판정 유지 |
| 지우 3학년 | 47 | 0 | 홀 근무·LED 영업·일반 연구원 제거. 상담 준비 참고 9건 |
| 지우 4학년 | 47 | 0 | 같은 오추천 제거. 상담 준비 참고 9건 |
| 서준 시제품 제작비 | 0 | 0 | 준비 참고 5건. 분야 적합성 보완 필요 |
| 서준 판로 상담 | 0 | 0 | 관련 원문 추가 확보 필요 |

수량 감소만으로 정밀도 향상을 판단하지 않는다. 지우의 빈 추천은 새 상담 공고와 유효한 모집·지원 조건 보완이 필요함을 보여준다. 민지 상위 후보 중 제목만 있는 기존 분류 공고는 업무 원문을 추가 확인해야 한다.

로컬 브라우저에서도 새 검색 API를 사용해 두 시연 계정의 목록을 확인했다. 홀 근무·LED 영업·일반 연구원 공고가 맞춤 화면에 나타나지 않고, 지우의 준비 참고에서 이음심리상담연구소 인턴을 확인했다. 브라우저 오류는 0건이었다. 기본 시연 날짜는 11월 22일이며 가상 공고도 포함하므로 화면 개수는 위의 실제 공고·11월 24일 고정 비교와 다르다. 이 화면에서는 지우 맞춤 11·참고 8, 민지 맞춤 39·참고 3이었다.

회귀 검사는 API 420개, 웹 56개 테스트와 TypeScript·수정한 추천 모듈의 ESLint 검사를 통과했다.

## 재실행

저장소 루트의 PowerShell에서 실행한다.

```powershell
Push-Location api
.\.venv\Scripts\python.exe -X utf8 -m app.career.evaluate_retrieval --fixture ../docs/eval/opportunity-relevance-v1.json --output ../docs/eval/retrieval-v1-results.json
Pop-Location
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/evaluate-opportunity-recommendations.mjs
```

합성 평가기는 메모리 DB를 사용한다. 실제 비교기는 로컬 공개 DB를 읽기 전용으로 열고 메모리 색인에서 평가한다. 실제 비교 결과에는 질의·공고 ID·버전·상위 인용을 저장한다. 로컬 DB 내용이 바뀌면 실제 비교 결과도 달라진다. 키워드 지표와 임베딩/RRF의 효과는 각각 측정해야 한다.
