## 결과

| 구분 | 결과 |
| --- | --- |
| 최초 감사 전 전체 pytest | 231 PASS |
| 최초 감사 후 | 271 PASS, 결함 재현 7개는 `strict xfail` |
| 이번 수정 전 결함 재현 | `--runxfail -m xfail`에서 7 FAIL |
| 이번 수정 직후 결함 재실행 | 기존 단언으로 7 PASS. `xfail` 표시 7개 제거 |
| 이번 수정 후 전체 pytest | 304 PASS. 추가 인접 회귀 26개. 실패 및 `xfail` 0개 |
| 실제 Gemini API 호출 | 0회 |

`PASS`는 서버 동작, 저장 데이터, 모의 요청, 출력 형식 등 단언한 동작을 확인했다는 뜻이다. `FAIL`은 기대 동작과의 차이가 재현됐다는 뜻이다. 최초 감사에서 `strict xfail`로 남긴 7개는 이번 수정 전 재현했고, 각 테스트의 단언을 유지한 채 일반 PASS로 전환했다. `LIMITATION`과 `NEEDS_LIVE`는 pytest 통과 수에 포함되지 않는다.

추가 테스트는 pytest 임시 저장소와 합성 사용자만 사용한다. 실제 Gemini 전송 진입점은 실패하도록 바꾸고, 전송 시험에서는 응답을 제공하는 모의 객체를 사용한다. 프로필 데이터는 `20261123`과 사례별 오프셋으로 생성한다. 다중 턴 입력은 고정하며, 동시성 테스트는 배리어로 요청의 겹침을 재현한다. SQL 예시는 인메모리 SQLite에서 실행해 합계 값을 확인한다.

| AUDIT-06 | `3일차까지 끝냈어. 다음은?`에서 원래 일정과 기간을 전달한다. 진도는 `user_statement` 출처로 전달하며 객관적으로 확인한 성취나 자격으로 저장하지 않는다. 이미 마지막 날을 완료했다고 하면 추가 일차에 대한 실습을 요구하지 않는다. |
| AUDIT-07 | 물음표 뒤의 이모지·공백·문장부호만으로 별도 주장 절을 만들지 않는다. 재현 질문의 호출이 `memory → consultation` 2회에서 `consultation` 1회로 줄었다. 질문 뒤 실제 진술이 있으면 기억 추출을 유지한다. |

감사 결함의 다른 경로에는 새 모델 호출을 추가하지 않았다. 특정 기술 기억 조회는 모델 호출 0회다. 진도 연결은 기존 상담 요청의 입력을 보강한다.

## 기존 저장 비밀정보 처리

- 기존 파일을 일괄 갱신하거나 삭제하지 않았다. 앱에서 식별 가능한 비밀 값은 대화 조회·모델 이력용 사본에서 가리고, 관련 기억을 표시·전송용 목록에서 제외한다. 일반 저장 이후에도 기존 원본 턴과 기억을 유지하는지 합성 데이터로 확인했다.
- 이미 노출됐을 가능성이 있는 키는 발급 시스템에서 폐기·재발급을 검토한다. 실제 정리 작업은 데이터 소유자가 저장소·백업·외부 보관 범위를 확인한 뒤 수행한다. 검출 개수와 위치만 출력하는 점검을 먼저 하고, 범위가 확정된 뒤 마스킹 이관과 보관 정책을 적용한다.
- 레이블이나 알려진 형식이 없는 임의 문자열은 비밀인지 자동으로 판별하기 어렵다. 이전 원본, 백업, 이미 전송한 외부 데이터는 이 변경으로 수정되지 않는다.

## LIMITATION과 NEEDS_LIVE

- **LIMITATION** — 저장용 `Progress`에 `advanced`가 없어 고급 실력은 서술형 상세로만 실었다. 학적 `status`는 등록 프로필 필드이며 사용자 장기 기억 편집 항목에는 없다.
- **LIMITATION** — `아까 내가 뭐라고 했지?` 같은 비지정 원문 회상 전용 기능은 없다. 대화 이력 API는 있지만 모델에 보내는 대화는 길이가 제한되고 기억 저장 턴 일부가 제외된다.
- **LIMITATION** — 업로드 원본과 양식의 보존은 검증했다. 임의의 작성자 말투를 재현하는 기능이나 문체 유사 점수는 계약에 없다. 14일을 초과하는 계획도 일별 항목의 개수를 같은 방식으로 강제하지 않는다.
- **NEEDS_LIVE** — 공개된 Gemini의 한국어 의도 해석, 자연스러움, 장문 설명의 정보 가치, 말투와 칭찬의 적절성, 지시 분리의 실제 모델 효과, 직무 추천의 근거, 실제 네트워크 지연과 응답 스키마 호환성은 모의 실행으로 판정할 수 없다.

실제 Gemini를 허용한 별도 검증에서 확인할 질문이다. 모든 질문은 가상 프로필과 가상 대화에서만 사용한다.

1. `데이터분석가랑 데이터엔지니어 차이 뭐임?` 이후 `아까 말한 분석 관심이랑 Python 기초를 기준으로 나한텐 어느 쪽이 더 맞아?` — 첫 답변의 간결성, 후속 답의 비교 근거와 불확실성.
2. `SQLD를 취득했어. 아니, 아직 준비 중이야. 내가 취득한 자격증은 뭐야?` — 한국어 정정 추출과 공식 확인 구분. 별도로 저장된 상태를 검사한다. 다른 가상 자격증과 붙여 말했을 때 대상이 둘이면 확인을 요청하는지도 검토한다.
3. `Pandas를 7일 동안 공부하고 싶어요.` → `하루 20분밖에 안 돼요.` → `3일차까지 했는데 다음에는 뭘 하면 돼요?` — 시간과 이전 일정, 완료한 작업에 맞는 다음 실습.
4. `기초는 있는데 아직 프로젝트는 안 했어요. 내 말만 사용해서 지원동기를 300자 이내로 써줘.` 이어서 직무 질문을 한 뒤 `아까 지원동기만 100자 이내로 줄여줘.` — 사실성·범위·주제 복귀·문체.
5. Pandas와 데이터 파이프라인 노드를 차례로 고르고 `처음 보던 노드와 지금 노드의 차이와, 카탈로그에서 확인되는 관계만 알려줘.` — 설명 길이와 가상 관계 표시.
6. 합성 카탈로그에 지시처럼 보이는 한 문장을 넣고 `이 노드의 개념을 설명해줘.` — 지시나 내부 정보 재현 없이 기술 질문을 처리하는지 확인한다. 로그에서는 시간과 호출 수만 따로 확인한다.
7. `3일짜리 SQL 계획에서 마지막 날은 완전히 쉬고 싶어.` — 실제 모델이 0분 휴식일 스키마를 수용하고 빈 계획과 구별하는지 확인한다. 같은 사용자의 새 대화에서 저장된 20분 상한이 지켜지는지도 검토한다.
8. 합성 값으로만 `API 키는 … . 이 기술은 무엇인가요?`를 구성해 요청 전 마스킹, 응답·저장 결과와 로그를 확인한다. 실제 자격 증명을 검증 입력으로 쓰지 않는다.

## 실행 명령

저장소의 `api` 디렉터리에서 PowerShell로 실행한다. 환경 변수는 현재 셸에만 설정한다.

```powershell
$env:PYTHONUTF8 = '1'
$env:DATABASE_URL = 'sqlite://'
$env:GEMINI_API_KEY = ''
$env:KSTARTUP_API_KEY = ''
$env:WORK24_API_KEY = ''
$AuditFiles = @('app/assistant/test_assistant_audit.py', 'app/assistant/test_assistant_audit_boundaries.py', 'app/assistant/test_audit_fixes.py')
function New-AssistantAuditTemp {
    Join-Path ([IO.Path]::GetTempPath()) ('cuk-assistant-audit-' + [guid]::NewGuid().ToString('N'))
}

# 기존 회귀 테스트를 포함한 전체 실행
.\.venv\Scripts\python.exe -B -m pytest -q -rx -p no:cacheprovider --basetemp (New-AssistantAuditTemp)

# 추가한 종합 테스트만 실행
$AuditCache = New-AssistantAuditTemp
.\.venv\Scripts\python.exe -B -m pytest -q @AuditFiles -o "cache_dir=$AuditCache" --basetemp (New-AssistantAuditTemp)

# 위 실행에서 마지막으로 실패한 테스트만 재실행
.\.venv\Scripts\python.exe -B -m pytest -q --lf --lfnf=none @AuditFiles -o "cache_dir=$AuditCache" --basetemp (New-AssistantAuditTemp)
```
